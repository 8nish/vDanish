Module 1: Network services without NSX Edge nodes

In VCF 9.1 a VPC gets north-south services such as NAT and DHCP without a Tier-0 gateway or an edge cluster. Routing happens on the hosts, and a small Virtual Network Appliance (VNA) cluster takes care of the stateful parts like NAT.

Default outbound NAT created an SNAT rule by itself: traffic from 10.13.13.0/24 is translated to 10.1.8.140, an address allocated directly from the External Connection IP block. That is what lets the private subnet reach the outside without its own external IP, and no edge node is involved.

Module 2: Control over cross-VPC communication

The goal: two Community VPCs, Finance and Marketing, isolated from each other, and a Shared Services VPC with a Promiscuous policy that both can reach. The VPCs come from VCF Automation, and NSX applies the connectivity policies, with no firewall rules involved.

Community and Promiscuous work like private VLANs: a Community VPC can reach the Promiscuous VPC but not another Community, and the Promiscuous VPC can reach everyone.

The connectivity profiles are where to experiment with that.

Key takeaways

  • VPCs in VCF 9.1 get NAT, DHCP and north-south services without NSX Edge nodes; a VNA cluster handles the stateful parts.
  • Default outbound NAT creates the SNAT rule for you, using an address from the external connection's IP block.
  • The same VPC can be built from vCenter or from a VCF Automation organization, with namespaces, VM load balancers and VKS clusters on top.
  • Private - TGW subnets can reach each other across VPCs; connectivity policies narrow that down without firewall rules.

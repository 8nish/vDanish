Module 4: vSAN stretched cluster

A stretched cluster spreads one vSAN cluster across two sites, with a witness host that only holds metadata:

In Site B: cluster-mgmt-01b > Configure > vSAN > Fault Domains > Configure Stretched Cluster:

esx-01b and esx-02b in the preferred domain, esx-03b and esx-04b in the secondary:

The witness has to pass the compatibility checks. Here it's esx-11b:

If I understood it right, the witness is the tie-breaker. If the link between the two sites drops, it decides which side keeps the data online so both sides don't carry on separately.

Key takeaways

  • Auto-RAID picks the RAID level and failures to tolerate based on the cluster size.
  • ESA claims new disks by itself, so scaling out is mostly moving hosts in.
  • Run the data migration pre-check before taking a host out.
  • Back up a native key provider right after creating it.
  • A stretched cluster needs a witness. Site affinity keeps a VM's data on one site.
  • Protection groups with name patterns pick up new VMs automatically.
